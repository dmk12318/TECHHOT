# 类别方案

> **2026-10-10 更新：「多个领域并进一个实例」这个前提已作废。**
> 综合站（DAILY HOT）改成**导航页 + 六个板块各自独立成站**，理由见 `records/决策记录.md`
> 2026-10-10 那条。本文件原名《类别方案与缝合规则》，改名的同时把过时前提一并撤了。
>
> 这份文件现在管三件事：① 科技板块的六个类别怎么分；② 形态标签词表；③ 改类别时必须守的规矩。
> **加板块的做法已经变了：不再往同一个实例里追加 key，而是另起一个独立站。**

## 一、你拍板的四条（2026-10-09）

1. **缝合要求（2026-10-10 改）**：原话是「今天的划分，将来多领域并成综合站时不能互相影响」。
   现在综合站改成六个板块各自独立成站，不再并进一个实例。这条遂改成：
   **各站自己的 key 上线后不得再改；加板块一律另起一个独立站。**
2. **新能源与汽车合为一类**。
3. **取消「互联网平台」类；人工智能的新闻单独归「人工智能」**。
4. **类别名一律用书面语**。

## 二、先看清引擎给了哪几个轴（这是方案的地基）

读了引擎的代码，能用的轴就三个，各自管的事不一样，不能混：

| 轴 | 引擎里的载体 | 它决定什么 | 上线后能不能改 |
| --- | --- | --- | --- |
| **板块** | `CATEGORIES` 里的 `section` 字段 | **只决定日报、周报、月报怎么分节**（`sectionOf(category)` 分组）。首页、全部动态、接口都不看它 | 能改，但会让已出的报告重算分节 |
| **频道（领域细类）** | `CATEGORIES`（`key`、`label`） | 首页和全部动态的筛选栏、网址 `/all?category=`、分类 RSS `/feed/category/<key>.xml`、公开 API 的 category | **`key` 上线后不能改**，改了就断网址和订阅 |
| **形态与其它** | `CATEGORY_TAGS`（每篇第一个标签）、`TOPIC_TAGS`、`ITEM_TYPES`、`ENTITIES`、`topics.json` | 卡片上的标签、标签筛选、主题页、评分权重 | 随时增删 |

两个必须知道的引擎事实：

- **筛选栏是一行扁平标签，不按 `section` 分组。** `CategoryTabs` 直接把所有类别铺成一排。
  所以类别数量直接等于筛选栏长度。
- **`commentary: true`（日报对"评论类跟进"的降级处理）只能挂在类别上**，标签替代不了。
  每个站都要保留一个评论类类别，否则日报会开始被观点和教程刷屏。

## 三、类别怎么落到代码里

一句话：**类别就是频道，板块只用 `section` 表达，不单独占一个类别。**

| 轴 | 现在（一个板块一个站） | 加板块时 |
| --- | --- | --- |
| 板块 | 所有科技类别的 `section` 都写 **`科技`** | 新站自己写自己的板块名，**科技站一个字都不动** |
| 频道 | 6 个类别（见下表），key 带 `tech-` 前缀 | 新站自己起 key，**老站的 key 一个字都不动** |
| 形态 | 第一个标签用形态词（见第四节） | 通用，必要时追加 |
| 公司、方向 | `ENTITIES`、`TOPIC_TAGS`、`topics.json` | 各站自己维护 |

### 科技板块的六个类别（v1）

| key | 类别名（书面语） | section | 收什么 |
| --- | --- | --- | --- |
| `tech-ai` | 人工智能 | 科技 | 模型、算力、AI 产品与治理；**原「互联网平台」的内容也并到这里** |
| `tech-consumer` | 消费电子 | 科技 | 手机、电脑、平板、可穿戴、家电的发布定价、系统更新、召回 |
| `tech-chip` | 半导体 | 科技 | 芯片设计与制造、制程、产能、出口管制、设备材料、涨价缺货 |
| `tech-telecom` | 通信 | 科技 | 运营商资费与网络建设、5G/6G、卫星互联网、频谱监管 |
| `tech-auto` | 汽车与新能源 | 科技 | 车企价格与技术路线、辅助驾驶法规与事故、召回；光伏、储能、电池、电价补贴 |
| `commentary` | 观点与解读 | 观点与解读 | 评论、解读、预测。带 `commentary: true`，日报只放进快讯 |

**与代码对齐的一点**：`engine/industry/taxonomy.ts` 里另有一个兜底类别 `industry`（标签「产业动态」，
`section` 也写「科技」）。引擎要求它必须存在——没归上类的资料会落进它所在的节；
少了兜底，没归类的资料会掉进最后一节（也就是观点栏）。它不计在「六个类别」里。

### 为什么 key 还带 `tech-` 前缀（历史原因，别照着推广）

当初那么定，是假设将来把多个领域并进**一个**实例：两个板块若出现同名细类（科技有「产业政策」、
财经也有「产业政策」）就会撞 key，而 key 上线后不能改。

现在改成独立站，撞 key 已经不可能发生。所以 `tech-` 前缀**只是既成事实**——已经在库里、
已经出现在网址和分类 RSS 里，因此不改。新起的站不必照着加前缀。

## 四、形态标签（每篇资料的第一个标签）

按书面语写，跨板块通用：

```
产品发布 / 技术进展 / 监管与政策 / 事故与安全 / 供应链与价格 / 财报与经营 / 合作与并购 / 研究突破 / 观点与解读 / 教程与方法
```

（`CATEGORY_TAGS` 的词表以这个为准；`TAG_SYNONYMS` 把模型常写的近义词统一过来，比如"融资""收购"→"合作与并购"。）

## 五、三条硬规矩（改类别之前先看）

1. **老 key 永不改、不删。** 库里已有的 key 会出现在网址、分类 RSS 和公开 API 里，
   改了，老的订阅和链接就断。要调整就新增 key、停用旧的。
2. **`section` 永远写板块名，不写细类名。** 日报分节的数量由**板块数**决定，不由细类数决定——
   科技站 6 个类别仍然只占日报里的一节「科技」。
3. **细类必须同时出现在 `CATEGORY_TAGS` 和 `topics.json` 的 `field` 组里。**
   这样万一哪天要把细类并回板块级，标签和主题页照旧能用，不至于推倒重来。

## 六、已知的代价（说在明处）

- ~~筛选栏会变长~~：**这条已经不存在。** 原先担心的是多个板块并进一个实例后，二三十个标签挤在
  扁平的一行筛选栏里放不下；改成独立站后，每个站只有自己那几类，一行放得下。
- **代价换到了别处：六个板块就是六份源清单 + 六轮门槛校准 + 六套运维。** 流程（找源、验可达、
  跑评测）能复用；**门槛和边界不能**，每加一块都要重新标样本、重跑评测。
  科技这一轮的做法与结果见 `docs/规范/科技板块选稿规范.md` 和 `records/决策记录.md`。
- **门户拿不到跨板块的主编视角。** 门户只列各站最热五条，不做跨板块去重，也不出综合日报。

## 七、两个口子已定（2026-10-09）

1. **原「互联网平台」的内容归「人工智能」。** 纯平台经营类的事（用户规模、收费、内容治理、
   重大故障）也按这个走——今天平台的大新闻基本围着 AI 转，宁可归得粗一点，也不新开一个类别。
2. **日报报头那个数字用 `tech-ai` + 「模型发布」标签 ＝「N 个新模型」。**
   以后想换成"N 款新品""N 款新车"，只改 `RELEASE` 这一处；不想要就设成 `null`，报头不显示这个数。
