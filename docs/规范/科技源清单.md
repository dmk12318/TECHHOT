# 科技源清单

另起的一份科技源清单，不沿用旧项目「每日新闻」的 219 条（见 `records/决策记录.md`）。

## 这份清单怎么来的

四步：**定口径 → 列候选 → 逐条实测 → 抓不到的走兜底**。

实测工具是 `scripts/check-feeds.ps1`（本项目自己的，可重复跑），候选表在 `scripts/feed-candidates.txt`，
兜底表在 `scripts/feed-fallback.txt`，原始结果在 `docs/规范/feed-实测.md` 和 `feed-实测-兜底.md`。

结果：

|  | 条数 |
| --- | --- |
| 候选 | 55 |
| 原生 feed 可用 | **36** |
| 走 Google News 兜底后可用 | **19**（19/19 全成功） |
| 最终拿不到入口 | 0 |

对比旧项目：219 条源里只有 72 条有原生 feed。差距不在源的质量，在**这次是先验可达性再入库**。

实测时间见两个实测文件；注意那是**本机走 VPN** 的结果，只证明"源端有 feed 且我们能取到"，
不代表以后 GitHub runner 上的结果——runner 在美国，通常更顺。

## 口径

**分级 `tier`**

| 分级 | 用在哪 | 精选门槛 |
| --- | --- | --- |
| `T1` | 公司官网、官方博客、政府部门、标准组织 | 低（一手，先看它） |
| `T1_5` | 官方社媒账号、身份明确的准官方 | 中 |
| `T2` | 媒体、行业媒体、个人 | 高 |

**其他字段**

- `participation_mode`：一律 `editorial`（进精选和全部动态）。暂时不需要只作热度证据的源。
- `site_fulltext` / `syndicate_fulltext`：**一律 `false`**。站内只显示摘要和原文链接，不复制全文
  ——这是决策记录里定下的口径，外文源也一样。
- `interval_minutes`：官方源 `120`，媒体 `60`。先这样，跑起来按各源实际更新量调。

**一个容易搞错的地方**：类别归属是**按篇判的，不挂在源上**。
「IT之家」既可能出一条消费电子的稿，也可能出一条半导体的稿，由模型按 `structure.md` 判断。
源上的 `tags` 只是给后台看的备注，不决定类别。

## 二、Google News 兜底（19 条）

这 19 条的**原站要么用 Cloudflare 拦我们（403）、要么那个 feed 地址已经失效（404 或返回网页）、
要么连不上**。改用 Google News 的按站检索 RSS 取标题和链接，**19/19 全成功**——
这个办法旧项目也验证过（当时 22/22）。

地址格式（中文源用 `hl=zh-CN&gl=CN`，英文源用 `hl=en-US&gl=US`）：

```text
https://news.google.com/rss/search?q=site:<域名>&hl=zh-CN&gl=CN&ceid=CN:zh-Hans
```

读者点进去会先过一次 Google，然后落到原站。旧项目也接受过这个代价。

**一个要提醒的**：引擎自带的示范源里就有一条坏地址——`https://deepmind.google/blog/rss.xml`
实测返回的是网页不是 feed（这条我也放进了兜底）。说明**示范配置也不能照抄，得验**。

## 三、还没做的

- **公众号源**：中国大陆很多一手信息在公众号上，但要极致了（Dajiala）的 key，按请求计费。
  按"只出模型费"的口径，**先不开**。
- **X（推特）账号**：要 SocialData 的 key，同样按请求计费，**先不开**。
- **按更新量调抓取频率**：等真跑起来，看后台（或日志）里各源的产出，再调 `interval_minutes`。
- **逐条复核分级**：现在 T1/T2 是按"是不是官方站"粗分的，上线前要过一遍。

## 四、下一步：转成引擎格式

引擎读的是 `engine/industry/sources.json`（首次启动时由 `scripts/seed.ts` 导入）。字段对应：

| 清单里的 | sources.json 里 |
| --- | --- |
| 源名 | `name`，`id` 用 `rss-<短名>` |
| feed 地址 | `kind: "rss"` + `config.feedUrl` |
| 分级 | `tier` |
| 官方站的 `owner_entity_id` | 对应 `taxonomy.ts` 的 `ENTITIES` id |
| 其余 | `participation_mode: "editorial"`、`site_fulltext: false`、`syndicate_fulltext: false` |

**注意**：`engine/industry/sources.json` 现在是 AIHOT 的 AI 示范源，替换它等于覆盖已有产物，
动手前要用户批准。库里已经导入的源不会被 `seed` 删掉，替换后要的清理方式再单独定。

## 五、替换已经做了（2026-10-09）

已经替换并导入：`engine/industry/sources.json` 现在就是这 55 条，`seed` 跑通

两件要记住的事：

- **同 id 的信源，`seed` 不会覆盖**（`ON CONFLICT DO NOTHING`）。实测撞上两条：
  `rss-openai-news`（示范源用的是 `openai.com/news/rss.xml`，我们表里是 `blog/rss.xml`）和

- **route B 没有后台**，所以"改配置"这件事不能只在界面上做。用的脚本是
  `engine/scripts/set-enabled-sources.ts`（开关信源）和 `engine/scripts/query.ts`（临时查询/小修）。
