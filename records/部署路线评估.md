# 部署路线评估

用途：给「部署路线」这个待定项提供判断依据。这里只放事实和代价，结论等用户拍板后写进 `records/决策记录.md`。

## 引擎是什么形状（已核实）

读了 `engine/docs/deploy.md`、`engine/apps/worker/src/main.ts`、`engine/apps/worker/src/schedules.ts`、
`engine/apps/web/server.ts` 之后，有三条事实决定了部署方式能有多自由：

1. **worker 是常驻调度器，不是「跑完就退」的批处理。** 它用 pg-boss 注册一批定时任务
   （采集、翻译、热度、出刊、备份、告警），靠进程一直活着等下一次触发。
   引擎里没有「把队列处理干净然后退出」的入口，也没有「按需跑一次」的命令行。
2. **网页是服务端渲染，一个端口同时管网页、后台 `/admin`、公开 API、MCP、图片代理和反馈提交。**
   它不是静态站点生成器，页面内容都是运行时查数据库。
3. **数据在 PostgreSQL。** 信源、资料、评分、事件、日报、站点设置全在里面。

一句话：这个引擎默认的形态就是「一台一直开着的机器 + 一个数据库」。

## 路线 A：Oracle Cloud Always Free 跑完整 Docker Compose

拿到手的：

- 引擎的全部功能都在：网页、后台、实时热度、公开 API、MCP、反馈、图片代理。
- 信源管理和选稿校准有界面（后台的「信源」「模型与评测」「SelectBench」页），换提示词后能马上跑评测。

已知代价：

- 注册要绑卡。绑卡本身不产生费用，但风控被拒是常见事，需要本人操作。
- Arm Ampere A1 的免费额度经常开不出来（热门区域长期无货），可能要等、要换区域，或者退而用更小的免费规格。
- 机器在海外，国内读者打开会慢一档。
- 得自己定域名和 HTTPS。

待核实（用户拍板前不要当成事实用）：

- Oracle 免费实例当前的申请难度和回收政策。
- 海外机房的国内访问速度，用哪家、哪个区域。

## 路线 B：GitHub Actions 定时跑 + 免费 Postgres + 静态页

拿到手的：

- 零成本、不用绑卡；每天定时出一份静态快照。

要自己写的胶水（按引擎结构估）：

1. **一次性驱动整条管线**：触发采集 → 等队列排空 → 确认出刊写完。引擎没有这个入口，得新写。
2. **把公开页面预渲染成静态文件**。React Router 支持 prerender，但页面数据来自运行时查询，
   要改成构建时取数；内容是「构建那一刻」的，不是实时的。
3. **静态版 RSS、站点地图、分享图**。

丢掉的东西（这是主要代价，不只是工作量）：

- 后台：信源管理、失败诊断、门槛校准（SelectBench）全没了，只能改文件。
- 实时热度、公开 API、MCP。
- 反馈表单、图片代理。
- 「某源挂了就标注数据截止时间」这类运行时逻辑没法即时体现。

待核实：

- `github.io` 作为发布地址在国内的可达性（对公职人员读者是硬伤，需要换托管或另想办法）。
- 免费 Postgres（Neon / Supabase）的免费额度是否够用、国内网络能否连通。

## 顺带记下两个备选（暂不建议）

- **把服务搬到 Cloudflare Workers + D1**：免费额度够小站用，但要把一个 Node 常驻服务改造成
  Workers 运行时，改动量比路线 B 还大。
- **本机常开 + 隧道对外**：零成本、功能全，但站点可用性绑在你这台 Windows 上，
  家用宽带当公职人员的固定网址不稳。

## 拍板前需要用户回答的三件事

1. **走 A 还是 B**（或者提出第三条）。
2. **站点放境内还是境外**：决定要不要备案，也决定国内读者的打开速度。
   注意这条和路线 A 有冲突——A 只能放海外机房（免费额度没有境内区域）。
3. **是否现在把本机 Node 升级到 24.11 以上**：引擎的 typecheck、测试、评测脚本都要求。
   不装的话，改完配置没法在本机验证，只能等服务器上跑。
