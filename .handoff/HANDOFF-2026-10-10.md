## 这一轮踩到并修掉的坑（新对话别重走）

1. React Router 的 `basename` 与 Vite 的 `base` 必须逐字一致（都带结尾斜杠）：预渲染是拿
   `basename` 拼 `${path}.data` 请求的，不一致会一路 404，而且**构建失败时不留报错**。
   这个坑连踩两次，第二次才定位到。
2. 预渲染产物会写进 `build/client/<前缀>/…` 多一层，而静态托管把产物根目录当站点根目录：
   导出时要把那一层提上来（`export-static.ts` 里那段）。
3. 写死在 HTML 里的地址（图标、manifest、RSS、`pool.json`）要自己加前缀，走
   `apps/web/app/lib/base-path.ts` 的 `sitePath()`；路由链接由 router 自己加。
4. CI 是 Linux，npm 不在 `node.exe` 旁边而在 Node 前缀的 `lib/` 下：导出脚本原来只找 Windows 那个位置，
   构建子进程直接失败且不留报错（已改成两处都找，并把子进程输出打出来）。
5. 分享图地址在页面里带着前缀（`/TECHHOT/og/…`），取回来和落盘都要先脱掉。
6. `robots.txt` 与 `manifest.webmanifest` 以前把**没渲染的模板**（`{{siteName}}`/`{{siteUrl}}`）
   原样发出去了，现在从 api 取渲染好的。
7. Pages 默认按 Jekyll 处理，会丢掉 `_.data` —— 产物根目录必须放 `.nojekyll`。
8. 本机跑 Web 测试前要 `npm run build -w @aihot/web`（普通构建）；预渲染过的产物不能拿来起网页服务。

## 顺手记下的工具与命令

- 本机起停站点（必须用 Windows PowerShell 5.1）：
  `powershell -ExecutionPolicy Bypass -File scripts\本机启动.ps1`（`-Stop` 停）。
- 本地导出（api 要活着）：
  `cd engine; node --env-file=.env scripts/export-static.ts --out static --skip-images`
  加 `--base http://127.0.0.1:8099/TECHHOT` 可以按子路径导一份来验体检。
- 静态站体检：`$env:STATIC_TEST_CHROMIUM='D:\Environment\playwright-browsers\chromium-1243\chrome-win64\chrome.exe'; node --test apps/web/tests/static-nav.test.ts`。
- 推代码要走代理：`git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push origin main`。
