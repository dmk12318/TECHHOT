## 1. 目标与完成标准

- **目标**：做一个中文科技新闻站（品牌 DAILY HOT），读者是「有阅读新闻需求与习惯的公职人员」。
  科技是**第一个板块**，做熟后复制到其他板块，最终合并成一个综合新闻站。
- **完成标准**：每天按固定时刻出刊，一件事一条；外文报道有中文标题与摘要；
  某个源抓取失败时如实标注数据截止时间、不假装最新；站点对外可访问。
- **不做**：不沿用旧项目「每日新闻」的 219 条源清单；不复制全文、不绕付费墙；
  不用需要绑卡或长期租金的付费服务器；科技只做门户意义上的科技（消费电子、半导体、通信、
  互联网平台、新能源、汽车智能化），不向别的板块蔓延。

## 3. 已否决的方案（别重走）

- **在旧项目「每日新闻」里改造** —— 两套管线（Python+SQLite vs Node+PostgreSQL）并存互相拖累，
  且旧项目还要继续出刊当断更期的保底。
- **科技板块只做 AI** —— 等于复刻 AIHOT 本身，没有差异化。
- **沿用旧项目 219 条源清单** —— 分级与口径对不上，筛选成本高于重找。
- **从零自己写引擎** —— 聚簇、热度、后台、评测要几周，而那些是领域无关的。
- **用 AIHOT 的名字和 Logo** —— 授权不允许（MIT 不覆盖名称与 Logo）。
- **租按月计费的 VPS** —— 与「只出模型费」的成本上限冲突。

## 6. 未完成项与已知风险

1. **部署路线未拍板，是硬阻塞**：路线 A（Oracle 免费云跑完整 Docker）与
   路线 B（Actions + 免费数据库 + 静态页）各是独立的一整套活，选错要返工。
   `records\决策记录.md` 末尾已标注「不要擅自按其中一条开工」。
2. **引擎最值钱的是评测闭环，最容易跳过**：不标样本、不校准门槛，站点就选不准。
   这是唯一决定「能不能看」的一步。
3. **翻译与「不复制全文」的口径冲突尚未落实**：已决定启用翻译，但站内展示到什么程度
   还没定。目前只能靠 `site_fulltext`、`syndicate_fulltext` 保持默认关闭来兜。
4. **`engine/` 是嵌套 git 仓库**（自带 `.git`，保留才能拉上游更新），而 DAILY HOT 自身
   还没有 git 仓库。将来 `git init` 时要决定：把它加进 `.gitignore`，还是转成 submodule。
5. **`docs\规范\` 里是骨架自带的视频规范**（`视频风格规范.md`、`字幕规范.md`），与新闻项目
   完全无关，**尚未删除**（删文件需另行授权）。
6. **本机 Node v22 跑不了评测脚本**，需升到 24.11+，或在容器里跑。
7. **旧项目仍在跑，两套并存有时间和成本压力**，且旧项目的自动化配置尚未清理。
