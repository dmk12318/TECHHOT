# 环境说明（阶段 0 全流程）

目标：从这台只有 Node 22、没有数据库的 Windows 机器，走到「本机把引擎跑起来、能打开页面」。
做完这份教程，`docs/执行清单.md` 的阶段 0 就打完了。

预计一个晚上。时间主要花在 `npm ci`（几分钟）和第一次建表灌数据上。

## 你要亲自做的三件事

| 谁 | 做什么 | 为什么我代替不了 |
| --- | --- | --- |
| 你 | 在管理员 PowerShell 里跑两行换 Node | 目录没给写权限，我这边是非提权终端 |
| 你 | 注册 Neon、把连接串给我 | 要邮箱和登录 |
| 你 | 选一家模型、给 key | 要账号（模型费是本项目唯一允许的支出） |

## 第 1 步：把 Node 升到 24

引擎写死了 `node >=24.11`（见 `engine/package.json`），本机是 v22.23.3，跑不了。
Node 24.21.0 的 zip 已经下到 `D:\Environment\`，SHA256 和官方对得上，
解压在 `D:\Environment\node-v24.21.0-win-x64`，单独跑 `node -v` 得到 v24.21.0。

卡在最后一步：`D:\Environment\nodejs` 这个目录，你的账号只有「读取和执行」权限，
重命名和覆盖都会被系统拒绝。在**管理员** PowerShell 里跑下面两行（会弹 UAC，点同意）：

```powershell
Rename-Item -LiteralPath 'D:\Environment\nodejs' -NewName 'nodejs-v22.23.3-backup'
Rename-Item -LiteralPath 'D:\Environment\node-v24.21.0-win-x64' -NewName 'nodejs'
```

重开一个终端验证：

```powershell
node -v   # 应该是 v24.21.0
npm -v    # 应该是 11.x
```

要回退就把两个目录名换回来，旧版原样留在 `nodejs-v22.23.3-backup`，稳了再删。

顺带一个发现：那个目录以前就不可写，说明 `npm install -g` 装全局包**一直是失败的**。
换到新目录后这个毛病一起好了。

## 第 2 步：建 Neon 免费库

细节全在 `scripts/Neon免费库说明.md`（额度、计费口径、超额会怎样、备份限制都在里面）。
这里只列要做哪几件事：

1. 注册 https://neon.com ，新建项目：**Postgres 版本选 17，区域选美东**。
2. 拿 **direct** 连接串（连接串面板上那个 Connection pooling 开关切到不带 `-pooler` 的那串）。
3. 再建库：`dailyhot_test`（跑测试）先看有没有，没有才建；`postgres`（测试代码要连它建副本库）
   —— 实测新建的项目里本来就有，报 `already exists` 就跳过。
4. 在 SQL Editor 里跑 `CREATE EXTENSION IF NOT EXISTS pg_trgm;`，确认扩展能装。

## 第 3 步：装引擎依赖

```powershell
cd 'D:\File\Codex\DAILY HOT\engine'
npm ci
```

几分钟。如果卡住或者特别慢，换国内镜像重来一次：

```powershell
npm ci --registry=https://registry.npmmirror.com
```

装完先跑一次不需要数据库的检查，确认 Node 和依赖都对了：

```powershell
npm run typecheck
```

## 第 4 步：生成 .env

在 `engine/` 下：

```powershell
node scripts/init-env.ts --llm-key <你的模型 key>
```

它会生成 `engine/.env`，填好随机密钥和后台管理员密码，并把密码**打印一次**
（记下来，登录 `/admin` 要用；也可以事后翻 `.env` 里的 `ADMIN_PASSWORD`）。

然后手工改三处：

1. **数据库**。把这两行取消注释（`.env.example` 里本来注释着）：

   ```dotenv
   DATABASE_URL=postgresql://<user>:<password>@ep-xxx.<region>.aws.neon.tech/neondb?sslmode=require
   API_BASE_URL=http://127.0.0.1:3001
   ```

2. **模型**。`.env` 默认那套是引擎作者的网关写法：`LLM_MODEL=deepseek-flash`。
   用官方 DeepSeek 接口时，模型名是 `deepseek-chat` 或 `deepseek-reasoner`，
   而且官方接口不认 `LLM_EXTRA_JSON` 里的 `thinking` 参数，那行要删掉。
   先问接口自己有哪些模型，别猜：

   ```powershell
   curl.exe -sS https://api.deepseek.com/v1/models -H "Authorization: Bearer <key>"
   ```

   `.env.example` 里还写着千问（`dashscope`）和智谱（`glm`）的现成写法，用哪家抄哪家。

3. **安全阀**。这两行必须是 `true`——引擎的开关只认小写 `true`，
   写成 `1`、`yes`、`TRUE` 都算**关**：

   ```dotenv
   COLLECT_ENABLED=true
   MODEL_CALLS_ENABLED=true
   ```

`.env` 已经在 `engine/.gitignore` 里，不会被提交。
这台机器现在挂着 VPN（TUN 模式，系统级），抓海外信源不用再设 `EGRESS_PROXY_URL`。

## 第 5 步：建表、灌信源

```powershell
node --env-file=.env scripts/migrate.ts
node --env-file=.env scripts/seed.ts
```

第一条建好全部表和索引（`pg_trgm` 就是这时装的），第二条把 `industry/sources.json` 里的信源灌进去。
两条都幂等，重复跑不会重来——`migrate` 按文件名记账，`seed` 只补库里没有的信源。

## 第 6 步：把站点跑起来（阶段 0 的验收）

先构建网页（生产模式下网页读的是构建产物）：

```powershell
npm run build -w @aihot/web
```

然后三个进程，各开一个终端，都在 `engine/` 下：

```powershell
$env:NODE_ENV = 'production'; node --env-file=.env apps/api/src/main.ts
$env:NODE_ENV = 'production'; node --env-file=.env apps/worker/src/main.ts
cd apps/web; $env:NODE_ENV = 'production'; node --env-file=../../.env server.ts
```

打开 `http://localhost:3000`，`/admin` 用第 4 步那个密码登录。

**动手前先知道会发生什么**：worker 一启动就会开始采集和处理。示范信源第一次导入的
152 条资料大约要跑 930 次模型调用、半小时处理完——这是真花钱的。
阶段 0 只是想验证环境，不想花这个钱，就把 `COLLECT_ENABLED` 和 `MODEL_CALLS_ENABLED`
临时改成 `false`，页面照样能打开，只是没有内容。

验收标准：首页、`/all`、`/admin` 都能打开，后台「信源」页能看到信源列表。

## 第 7 步：跑检查

```powershell
npm run typecheck

$env:DATABASE_URL = 'postgresql://<user>:<password>@ep-xxx.<region>.aws.neon.tech/dailyhot_test?sslmode=require'
npm test

node scripts/smoke.ts --base http://localhost:3000
```

`typecheck` 不需要数据库；`npm test` 会自己建副本库（所以库名必须以 `_test` 结尾）；
`smoke.ts` 要站点正在跑，它会把首页到 `/admin/login`、RSS、站点地图、OpenAPI 挨个打开看是否应答。

## 本机 PostgreSQL（跑测试用）

引擎的测试框架会给**每个测试文件复制一份"模板库"**（`CREATE DATABASE … TEMPLATE`），
而 Postgres 要求复制时模板库上没有别的连接——Neon 的计算节点内部进程会挂在每个库上，复制必然被拒。
所以测试必须用一个本机的 Postgres。

装的是免安装版，在 `D:\Environment\postgres`（17.11，数据目录 `data`，日志 `server.log`）：

```powershell
# 启动 / 停止（开机后第一次跑测试前要启动）
& 'D:\Environment\postgres\bin\pg_ctl.exe' -D 'D:\Environment\postgres\data' -l 'D:\Environment\postgres\server.log' -o '-p 5432' -w start
& 'D:\Environment\postgres\bin\pg_ctl.exe' -D 'D:\Environment\postgres\data' stop

# 跑全套测试（库名必须以 _test 或 _ci 结尾）
cd 'D:\File\Codex\DAILY HOT\engine'
$env:DATABASE_URL = 'postgres://postgres@127.0.0.1:5432/dailyhot_test'
$env:PATH = 'D:\Environment\postgres\bin;' + $env:PATH   # 备份测试要 pg_dump / pg_restore
npm test
```

初始化过的东西（换机器时要重做）：`initdb … --auth=trust`、建库 `createdb dailyhot_test`。
本地连接是 trust 认证、只监听 127.0.0.1，不需要密码。

**本机跑会失败的那几类**（都是 Windows 差异，CI 的 Linux runner 上会通过）：

- `SIGTERM …` 的 5 个：Windows 没有真正的信号。
- `backup` 里用到 `tar -T /dev/null` 的 4 个：Windows 没有 `/dev/null`。
- `outbound-protocol.standalone`：要 `openssl`，Windows 默认没有。
- 全套并发跑时，偶尔有几个文件在建"模板库副本"时报 `test failed`（没有细节）——
  这是六个测试文件同时复制模板库、Windows 文件 I/O 慢导致重叠，**单独跑就过**。

**看失败清单时先把这几类排除**，剩下的才是真问题。

## 已知问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Rename-Item` 报 Access denied | 目录只给了读取权限 | 在管理员 PowerShell 里跑（第 1 步） |
| `database "postgres" does not exist` | Neon 默认只有 `neondb` | 建一个空的 `postgres` 库 |
| 测试报库名不对 | 引擎要求库名以 `_test` 或 `_ci` 结尾 | 用 `dailyhot_test` |
| 第一次连接要等好几秒 | Neon 免费版闲置会 scale to zero，要冷启动 | 正常现象，Actions 里每次跑都得等 |
| 改了 `taxonomy.ts` 或 `topics.json` 没生效 | **类别体系是编译进网页构建产物的**（实测确认：改完 taxonomy 后 `/all` 上还是老类别名）；`topics.json` 是站点启动时读 | 改完必须 `npm run build -w @aihot/web` 重新构建，再重启 web 进程 |
| `engine/` 下有个嵌套 git 仓库 | 它是从 AIHOT 直接克隆的，自带 `.git`，这样保留才能拉上游更新 | 本项目自己 `git init` 时把 `engine/` 加进 `.gitignore`，或转成 submodule（未定） |
| 本机没有 Docker | 路线 B 不需要常驻服务 | 不用管 |
| **放着不管一段时间，三个进程自己没了** | 用 Codex 会话里的后台方式起的进程，会话结束时可能被一起回收（日志里没有崩溃痕迹） | **本机启动一律用 `scripts/本机启动.ps1`**（用户自己在终端里跑，或用它起完再没人关就一直跑）。要停用 `-Stop`，它会顺手清掉卡住的定时任务 |
| **采集全部失败，错误是 `Blocked private address for <域名>`** | 本机的 VPN 是 TUN/fake-IP 模式，所有域名都解析成 `198.18.x.x`，引擎的防 SSRF 检查把这个网段当内网拦掉 | 本机调试在 `.env` 里设 `ALLOW_PRIVATE_NETWORK_FETCH=true`，并且用**非 production 模式**启动 api 和 worker（production 会拒绝启动）。它同时会跳过地址检查和 DNS 重绑定防护，所以只能本机用。生产 runner（美国）没有这种代理，不受影响 |
| 硬杀 worker 后采集就不动了 | 用 `Stop-Process` 杀掉 worker，pg-boss 的单例定时任务会卡在 `active` 状态（`expireInSeconds: 3600`），最长一小时才自动回收 | 清掉僵尸任务：`UPDATE pgboss.job SET state='failed', completed_on=now() WHERE state='active' AND started_on < now() - interval '2 minutes'`，再把 `sources.next_fetch_at` 设回 `now()` |
| **`eval-selection.ts` 的结果永远是"一条都没选上"** | **引擎脚本的 bug**：评测只跑「预筛 + 两次评分」，不跑写标题摘要那一步；但判定入选用的 `normalizeAnalysis.relevance` 只有在写完标题摘要后才可能是 `"pass"`，于是评测里每条都成了 `unknown`，门槛从 40 扫到 90 全是 `sel=0`。 | 别改引擎代码。用 `engine/scripts/calibrate-thresholds.ts`：它把预筛自己的标签（从回执里读）和分数配对，自己算门槛曲线和查准率/查全率。 |
| `test:standalone` 里 `outbound-protocol` 失败 | 它要调 `openssl` 生成测试证书，Windows 默认没有 | 不用管，CI 的 Ubuntu 上有；本机看其余 157 条即可 |
| 改完 `taxonomy.ts` 的标签词表后，模型还是打出旧标签 | `content-understanding.md` 里的主题与实体白名单是**硬编码**的，不读 `taxonomy.ts` | 两处一起改 |
| 有些文章一直"等材料"、取不到正文 | 直连取不到正文时会回落到 **Jina Reader**，它是按请求计费的，我们没配 key（"只出模型费"的代价）。实测只有约 3% 的文章命中（逐篇失败，不是整源） | **已决定接受**（见决策记录 2026-10-10）：引擎重试几次后按订阅摘要判断。别用 `summaryIsBody` 绕——那会让整个源放弃抓正文 |
